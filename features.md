# Features Specification

Service: services/uptime (Rust / Axum / SQLx / TimescaleDB / Redis)
- Регистрация сайтов для периодического мониторинга доступности с валидацией схемы URL (поддерживаются только http/https) и запретом передачи credentials.
- Строгая валидация входящих DTO (ограничение длины URL до 2048 символов, user_id до 128 символов).
- Многоуровневая SSRF-защита при регистрации и опросе ресурсов:
  - Обязательный предварительный DNS-резолвинг доменных имен в целевые IP-адреса;
  - Фильтрация приватных (RFC 1918), loopback (127.0.0.0/8), link-local, unspecified, broadcast, multicast и CGNAT адресов IPv4 и IPv6;
  - Проверка целевых IP по динамическому черному списку запрещенных хостов (`forbidden_ip` в базе данных);
  - Защита от DNS Rebinding атак через принудительный резолвинг сокетов (`resolve_to_addrs`);
  - Поддержка тестового режима для локальной разработки (`ALLOW_PRIVATE_IPS`).
- Двухэтапная регистрация и протокол подтверждения владения (HTTP-01 Challenge):
  - Перевод сайта при создании в статус `pending_verification` (`active = false`) для защиты от несанкционированного мониторинга чужих сайтов;
  - Генерация криптографического `challenge_token` с хранением в Redis с TTL;
  - Верификация (`POST /sites/{site_id}/verify`): защищенный опрос `{url}/upward`, сверка токена и активация ресурса;
  - Возможность перевыпуска challenge-токена для повторного подтверждения отключённого ресурса (`POST /sites/{site_id}/challenge`).
- Специализированный протокол `/upward` и интерактивные UI-виджеты:
  - Опрос целевого сервиса по пути `/upward` с получением расширенной JSON-телеметрии;
  - Поддержка типизированных виджетов: `badge`, `stat`, `gauge`, `sparkline`, `key_value`, `chart`, `row`, `column`, `text`;
  - Валидация типов виджетов по системному справочнику в таблице `widgets`.
- Защита от сетевых аномалий и DoS (Payload & Stream Protection):
  - Ограничение максимального размера ответа (по умолчанию 512 КБ) через проверку `Content-Length` и потоковый контроль байт (`bytes_stream`) при `Transfer-Encoding: chunked`;
  - Жесткий таймаут сетевого соединения (10 секунд на сайт);
  - Отключение следования редиректам (`Policy::none()`).
- Идентификация ресурсов с типобезопасными Newtype-структурами:
  - `SiteId(Uuid)`: уникальный идентификатор сайта с автоматической генерацией `gen_random_uuid()` в БД;
  - `UserId(String)`: владелец ресурса для изоляции данных клиентов;
  - `SiteUrl(String)`: целевой адрес ресурса;
  - `SiteStatus`: статус мониторинга ресурса (`idle`, `processing`).
- Фоновый параллельный опрос доступности целевых сайтов (Cron/Polling Worker):
  - Потоковый конкурентный опрос с ограничением одновременных сетевых задач через Tokio Stream (`buffer_unordered`, настраивается через `PING_CONCURRENCY`);
  - Настраиваемый размер батча через `PING_BATCH_SIZE`;
  - Автоматическая деактивация недоступных сайтов при сбое проверки;
  - Замер времени отклика (`duration_ms`) и сбор метаданных ответа в JSONB (`extra`).
- Отказоустойчивая выборка и распределение задач между воркерами:
  - Атомарный захват сайтов через CTE и `FOR UPDATE SKIP LOCKED`, исключающий конкуренцию и дублирование проверок между несколькими репликами сервиса;
  - Автоматическое восстановление зависших проверок (Dead Worker Recovery): возврат сайтов в обработку, если они зависли в статусе `processing` дольше 3 минут;
  - Автоматический возврат сайтов в статус `idle` и фиксация времени `last_check` после завершения раунда проверок.
- Высокопроизводительное пакетное сохранение замеров (Batch Insert):
  - Пакетная вставка всех замеров одного раунда в один SQL-запрос через `QueryBuilder` вместо одиночных вызовов к базе данных.
- Хранение временных рядов в TimescaleDB:
  - Гипертаблица `site_pings` с автоматическим партиционированием по времени;
  - Настроенная политика хранения данных (Data Retention Policy) с автоматическим удалением устаревших замеров старше 30 дней (`add_retention_policy`).
- REST API и модульный роутинг (паттерн NestJS-like модулей):
  - Модуль сайтов: `POST /sites` (создание), `GET /sites/{user_id}` (список сайтов с метаданными последней проверки), `POST /sites/{site_id}/verify` (верификация), `POST /sites/{site_id}/challenge` (перевыпуск токена);
  - Модуль пингов: `GET /sites/{site_id}/pings?user_id=...` (история замеров доступности за последние 30 дней для конкретного владельца);
  - Модуль сервера: `GET /health` (Liveness/Readiness проба оркестратора);
  - Инкапсуляция роутеров каждого доменного модуля в отдельных функциях `routes() -> Router<AppState>`.
- Автоматическая интерактивная документация OpenAPI (Swagger UI):
  - Генерация OpenAPI спецификации в compile-time через макросы `utoipa`;
  - Интерактивный UI по адресу `/docs` (`utoipa-swagger-ui`).

Service: services/identify (Rust / Axum / SQLx / PostgreSQL / Redis / Argon2 / RS256 JWT)
- Сервис идентификации, регистрации и аутентификации пользователей системы.
- Регистрация учетных записей по email и паролю (`POST /register/password`) с проверкой уникальности и валидацией email.
- Надежное хеширование паролей промышленным алгоритмом Argon2id со случайной солью, вынесенное в `spawn_blocking`.
- Аутентификация (`POST /login/password`) с генерацией связки токенов:
  - Access токен: короткоживущий JWT (15 минут), подписанный асимметричным ключом RS256 (RSA 2048-bit);
  - Refresh токен: одноразовый UUIDv4 токен, сохраненный в Redis с TTL (30 дней).
- Безопасная ротация токенов (`POST /refresh`, Refresh Token Rotation) с атомарным удалением использованного токена из Redis (`GETDEL`) для защиты от перехвата сессий.
- Децентрализованная верификация токенов в микросервисах через раздачу публичного ключа: `GET /keys/public` (JSON) и `GET /keys/public.pem` (raw PEM).
- Поддержка OAuth-провайдеров (`Google`) и аккаунтов без пароля.
- Health-check эндпоинт (`GET /health`) и интерактивный Swagger UI (`/docs`).

Service: services/bff (NestJS / TypeScript / pnpm / Zod / Orval)
- Backend-for-Frontend шлюз для клиентских приложений (Web/Mobile UI).
- Агрегация и проксирование запросов к внутренним сервисам монорепозитория (`uptime`, `identify`).
- Авторизация и валидация входящих клиентских RS256 JWT токенов через `JwtAuthGuard`:
  - Кэширование открытого ключа RSA в `KeyService`;
  - Извлечение идентификатора пользователя (`@CurrentUser()`) и проброс токенов (`@RawToken()`).
- Интеграция с Google OAuth 2.0 (`/auth/google`, `/auth/google/callback`) через `passport-google-oauth20`.
- Управление ресурсами мониторинга: регистрация сайтов, получение списка, запуск верификации, получение истории пингов.
- Строгая валидация входящих данных через Zod (`nestjs-zod`) и автогенерация API-клиентов через Orval.
- Единая точка входа для клиентских сессий и централизованная обработка ошибок (`handleUpstreamError`).
- Swagger UI документация на `/docs`.

Service: services/docs (Fastify / TypeScript / Swagger UI)
- Легковесный централизованный портал документации разработчика (порт 5000).
- Интерактивный Swagger UI с выпадающим списком для мгновенного переключения между спецификациями микросервисов: BFF, Uptime, Identify.
- Быстрые ссылки: `/bff`, `/uptime`, `/identify`, `/specs/bff.json`, `/specs/uptime.json`, `/specs/identify.json`.
- Отказоустойчивое получение спецификаций с живых сервисов с фолбэком на локальные оффлайн-схемы.
