# Features Specification

Service: services/uptime (Rust / Axum / SQLx / TimescaleDB)
- Регистрация сайтов для периодического мониторинга доступности с валидацией схемы URL (поддерживаются только http/https).
- Многоуровневая SSRF-защита при регистрации целевых ресурсов:
  - DNS-резолвинг доменных имен в целевые IP-адреса;
  - Фильтрация приватных (RFC 1918), loopback (127.0.0.0/8), link-local и неспецифицированных адресов IPv4 и IPv6;
  - Проверка целевых IP по динамическому черному списку запрещенных хостов (`forbidden_ip` в базе данных).
- Идентификация ресурсов с типобезопасными Newtype-структурами:
  - `SiteId(Uuid)`: уникальный идентификатор сайта с автоматической генерацией `gen_random_uuid()` в БД;
  - `UserId(String)`: владелец ресурса для изоляции данных клиентов;
  - `SiteUrl(String)`: целевой адрес ресурса;
  - `SiteStatus`: статус мониторинга ресурса (`idle`, `processing`).
- Фоновый параллельный опрос доступности целевых сайтов (Cron/Polling Worker):
  - Потоковый конкурентный опрос с ограничением одновременных сетевых задач через Tokio Stream (`buffer_unordered`);
  - Ограничение времени сетевого ответа (таймаут 10 секунд на сайт) с политикой следования редиректам (до 5 hops);
  - Замер времени отклика (`duration_ms`) и сбор метаданных ответа (`status_code`, доп. заголовки в JSONB).
- Отказоустойчивая выборка и распределение задач между воркерами:
  - Атомарный захват сайтов через CTE и `FOR UPDATE SKIP LOCKED`, исключающий конкуренцию и дублирование проверок между несколькими репликами сервиса;
  - Автоматическое восстановление зависших проверок (Dead Worker Recovery): возврат сайтов в обработку, если они зависли в статусе `processing` дольше 3 минут;
  - Автоматический возврат сайтов в статус `idle` и фиксация времени `last_check` после завершения раунда проверок.
- Высокопроизводительное пакетное сохранение замеров (Batch Insert):
  - Пакетная вставка всех замеров одного раунда в один SQL-запрос через `QueryBuilder` вместо одиночных вызовов к базе данных.
- Хранение временных рядов в TimescaleDB:
  - Гипертаблица `site_pings` с автоматическим партиционированием по времени;
  - Настроенная политика хранения данных (Data Retention Policy) с автоматическим удалением устаревших замеров старше 30 дней (`add_retention_policy`).
- REST API и модульный роутинг (паттерн NestJS-like модулей):
  - Модуль сайтов: `POST /sites` (создание ресурса), `GET /sites/{user_id}` (список отслеживаемых сайтов конкретного пользователя с метаданными последней проверки);
  - Модуль пингов: `GET /sites/{site_id}/pings?user_id=...` (история замеров доступности за последние 30 дней для конкретного владельца);
  - Модуль сервера: `GET /health` (Liveness/Readiness проба оркестратора);
  - Инкапсуляция роутеров каждого доменного модуля в отдельных функциях `routes() -> Router<AppState>`.
- Автоматическая интерактивная документация OpenAPI (Swagger UI):
  - Генерация OpenAPI спецификации в compile-time через макросы `utoipa`;
  - Интерактивный UI по адресу `/docs` (`utoipa-swagger-ui`).

Service: services/bff (NestJS / TypeScript / pnpm)
- Backend-for-Frontend шлюз для клиентских приложений (Web/Mobile UI).
- Агрегация и проксирование запросов к внутренним сервисам монорепозитория (`uptime`, `identify`).
- Авторизация и валидация входящих клиентских JWT-токенов:
  - Извлечение идентификатора пользователя (`user_id`) из JWT и передача его во внутренние микросервисы.
- Единая точка входа для клиентских сессий и обработки ошибок внешнего API.

Service: services/identify (Haskell / Scotty / Cabal)
- Сервис идентификации, регистрации и аутентификации пользователей системы.
- Генерация, подпись и валидация токенов доступа (JWT).
- Health-check эндпоинт (`GET /health`) для мониторинга работоспособности сервиса.
